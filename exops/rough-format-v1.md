# ラフ作成マニュアル｜画像＋操作フロー方式 v1.0

「ラフを作って」と依頼されたら、この方式を最初の提案として使います。対象の画面だけを画像で確認し、採用後に実装へ進むためのフォーマットです。

## 進め方

1. **範囲を揃える。** 対象画面、開始点、完了点、維持するUI、未確定事項を依頼・仕様書から確認します。関連があっても別メニューの案を勝手に作り込まず、未確定事項に記録します。
2. **共通基準を読む。** 案件で決めた画面寸法、文字、色、CTA、余白、配置の軸を使います。画面ごとに変えません。EX OPSの作例は1280×624 CSS px／DPR1です。他案件の寸法や配色をこれで上書きしません。
3. **流れを分ける。** 開始→入力・選択→確認・処理中→完了、加えて取消・失敗・結果不明・戻り先を必要な分だけ洗い出します。1状態につき1画像、見出しとIDを付けます。
4. **画像を先に作る。** 既存のSVG/HTML/CSS素材があれば同じ骨格で描画し、個別PNGへ書き出します。画像生成が適する場合も最終の寸法と見た目を実測します。ラフ制作のソースを先行した製品実装と扱いません。
5. **画像と説明をセットで見せる。** 一覧ではスタートからエンドまでの順番を示し、個別画像の下に次の3項目を添えます。
6. **3つの方法で確認する。** 画像の寸法・色・配置、別ブラウザでの共通座標と模擬操作、画像/リンク/文書/対象外保全を別々に照合します。直した部分は再確認し、未確認の実機・実API・実決済を合格にしません。
7. **採用を分ける。** 人間が採用した画像だけを各メニューの採用フォルダと台帳へ移し、仕様へ反映します。未採用は確認用として保持。採用後に必要なSVG化・製品実装・再確認へ進みます。

## 各画像に添える説明

- **入口・操作：** どの画面の何を押すか。何を入力・選択し、どのCTAで次へ進むか。
- **接続・保存：** どの注文/顧客/商品を参照するか。いつ何を保存し、どの結果で完了するか。模擬表示と実接続を区別します。
- **取消・失敗・戻り先：** 戻る/×/キャンセルでどこへ戻るか。入力やスクロールの保持、失敗・結果不明で止める操作を記載します。

## 提案の書き方

> 今回は○○画面だけを「画像＋操作フロー方式」で作成します。既存UIを維持し、開始・操作中・完了・例外の個別画像に、入口/保存/戻り先の説明を添えて確認します。

## 同梱物と使い方

- **index.html：** 画像一覧と一連の説明。ダブルクリックで開けます。サーバー・トンネル・ログインは不要です。
- **frames/、pages/：** 個別PNGと原寸ページ。作例35枚は今回の注文管理の未採用案です。
- **flow-definitions.json、flow-routes.json：** 画面と動線の定義。新しいラフはテンプレートをコピーして別の作業フォルダで編集します。
- **ソース/画像描画/：** 作例のHTML/CSS/JSと素材。見た目と模擬遷移の元データで、製品コード/実金融処理ではありません。
- **ソース/ギャラリー生成.py：** 画像・定義から一覧と個別ページを作る再利用用ソース。
- **ソース/画像を書き出す.cjs：** 任意の再出力用。Node.jsとPlaywrightが必要です。閲覧だけなら不要です。
- **テンプレート/：** 画面定義・動線説明・確認記録の空欄ひな形。
- **design-tokens.json：** EX OPS作例の色・文字・寸法。通常白、主CTA黒、戻る灰、強調青赤。案件の採用済み基準を優先します。

画像と定義を編集した後、`python3 ソース/ギャラリー生成.py`で一覧を再生成します。描画から再出力する場合は、同梱のソースREADMEを参照してください。

## 保存と再開

localhostや一時URLは確認用の入口です。停止してもHTML/PNG/ソースは消えません。このフォルダ一式、またはZIPを保存し、再開時はindex.htmlと本書を読みます。画像だけ・URLだけに依存せず、ソース/動線説明/共通基準をセットで保持します。

方式の保存は、作例35画像の採用や製品完成を意味しません。実データ、認証情報、内部議事録を公開用の一式へ混ぜません。
